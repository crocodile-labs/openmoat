# What protects each agent, on each OS

> **Read this when** you want to know, for your agent and your operating system, what
> checks its calls, what happens when the hook fails, and what the claim rests on.

`openmoat status` and `openmoat doctor` say what is in place on your machine. This page
says what each agent gets on each OS, and which tests show it. The tables are generated
from the agents' facts in OpenMoat's code and from the tests themselves, so they cannot
claim more than the tests show (ADR-079). `openmoat doctor --verbose` points here.

## Summary

- **hook: protected** means a real copy of the agent ran OpenMoat's hook for a tool call
  on that OS and OpenMoat's decision held, in a CI test or in the weekly run of the
  agents' latest releases. **preview** means `openmoat init` sets the hook up and its
  payloads are tested, but no real copy of the agent has been run with it there yet.
- **own sandbox: yes** means `openmoat init` writes the agent's own OS sandbox and a test
  runs commands under it; **preview** means it writes it, with no such test yet.
- **`openmoat run`** is the tier it starts the agent in ([SANDBOX.md](SANDBOX.md)):
  Isolated on Linux where bubblewrap works, Lightweight on macOS. **(preview)** means no
  test starts that agent, or any program, under it on that OS.
