### Security
- `openmoat proxy` now serves agent sessions only (ADR-044). Claude Code's new `SessionStart` hook gives each session's sandboxed commands a proxy credential of their own (signed, accepted for 24 hours, issued again at every start, resume, `/clear` and compaction), so the proxy records each request under that session, applies its taint (after the session reads a secret, its commands' connections to other hosts are refused) and its share of the connections. A request without a valid credential, from another local program or with a credential edited, borrowed from another session or expired, gets `407` and a `proxy-session` row. The key is `~/.moat/proxy.key`, which the default policy denies to agents (`kernel-self`); replacing it revokes every credential. Run `openmoat init` after upgrading so Claude Code gets the `SessionStart` entry, then start a new session ([#676](https://github.com/crocodile-labs/openmoat/pull/676)).
- Codex's proxy cannot send a session credential, so `openmoat proxy` now refuses what a Codex started with `HTTP_PROXY` hands on. `sandbox.proxy_serve_without_credential: true` serves requests that carry no credential, with no session, as before (`openmoat policy lint`, `doctor` and `status` warn about it); `openmoat run -- codex` gives each run a credential of its own. `openmoat status` and `openmoat doctor` say for each host sandbox whether its traffic carries a session ([#676](https://github.com/crocodile-labs/openmoat/pull/676)).
