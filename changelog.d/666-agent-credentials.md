### Security
- New default rule `agent-credentials` (hook only): the agent's own tools may neither read nor write the files where Claude Code, Codex, GitHub Copilot CLI, pi, Gemini CLI, OpenCode, Hermes Agent, OpenClaw and the Continue CLI keep their login, provider keys and OAuth tokens (OpenCode's `~/.local/share/opencode/auth.json`, Hermes Agent's `auth.json` and `mcp-tokens/`, Codex's `auth.json`, …), in a moved agent directory too; `pi auth print-api-key`, `pi auth print-bearer-token`, `opencode auth export` and `secret-tool lookup` are denied, and `claude setup-token` asks (`agent-token`). Under `openmoat run` each agent still reads its own login ([#666](https://github.com/crocodile-labs/openmoat/pull/666)).
- An agent running its own CLI to save an MCP server, turn one on or start an MCP OAuth sign-in (`claude mcp add`, `codex mcp add`, `gemini mcp add`, `opencode mcp add`/`auth`, `hermes mcp add`, …) asks (`runs-later`), as does a write of the Continue CLI's `~/.continue/config.yaml`; `mcp list` and `mcp get` are unchanged ([#666](https://github.com/crocodile-labs/openmoat/pull/666)).
- `openmoat status` and `openmoat doctor` warn, in one line, when an agent on the search path is a version with a published security advisory that a later version fixes, such as the OpenCode MCP OAuth command execution on Windows and WSL (1.0.137 to 1.18.32) and pi's `auth.json` write race (before 0.78.1) ([#666](https://github.com/crocodile-labs/openmoat/pull/666)).
- OpenCode's `OPENCODE_CONFIG_DIR` and the Hermes Agent profiles `openmoat init` finds get the protection of the agent's own configuration directory; Hermes Agent's `memory` and `skill_manage` tools are checked as writes of its `memories/` and `skills/`, so the session-taint and `runs-later` asks apply; `openmoat status` and `openmoat doctor` also warn about a project's `opencode.jsonc`, `.opencode/opencode.jsonc` and `.opencode/plugin/` ([#666](https://github.com/crocodile-labs/openmoat/pull/666)).
