### Added
- `unattended: review` in your own policy holds a call OpenMoat would leave to the agent (`defer`) for review when the agent would run it with no one asked, as far as its hook can see: Claude Code's `bypassPermissions` and `auto` modes, and `acceptEdits` for file edits and the file commands it approves; pi without a screen; Hermes Agent in YOLO mode or with approvals off; Antigravity CLI with `toolPermission: always-proceed`. Where Claude Code still asks (`auto`, `acceptEdits`) you are asked; where no one is, the agent receives a deny that says how to approve it (`openmoat allow --last`, or the approvals channel). The default stays `defer`, so nothing changes until you set it; a repository policy or a pack cannot set it. An OpenMoat from before this release refuses a policy with the key, and its guard then denies every call, so update the binary first (POLICY.md §5.4, ADR-102).
- `openmoat mcp accept` (and `openmoat doctor --accept`) asks whether to run a server it accepts as new through OpenMoat, as `openmoat init` asks about the servers it finds; Enter is yes, and a no is remembered (ADR-102).
