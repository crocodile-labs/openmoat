### Security
- `openmoat run` now keeps commands from writing every agent's configuration in the project: Cline's workspace hooks (`.cline/hooks/`, `.clinerules/hooks/`), Gemini CLI's project policy files, custom commands and subagents (`.gemini/policies/`, `.gemini/commands/`, `.gemini/agents/`), Claude Code's subagents, skills and slash commands, GitHub Copilot CLI's custom agents (`.github/agents/`) and OpenCode's commands were held for review only when the agent wrote them with its own tools, and a command it ran could write them. On macOS Seatbelt denies them wherever they are; on Linux, within the limits of each tier (ADR-090), existing ones are read-only, and a missing folder of them is made read-only for the session where the folder holding it exists directly in the project. Writing OpenCode's project agents (`.opencode/agents/`, `.opencode/agent/`) and skills (`.opencode/skills/`) now needs review, and commands under `openmoat run` cannot write them. Repositories often commit some of these folders: under `openmoat run` a `git pull`, `git checkout` or package install that changes them fails partway, and so does the agent's own tool when the agent runs inside `openmoat run`; do those outside `openmoat run`. Each agent's files that run later now come from its spec, and the default policy's agent lines in `runs-later` and `project-fs` are generated from it (ADR-091) ([#810](https://github.com/crocodile-labs/openmoat/pull/810)).
