### Security
- Every policy change is checked for widening: `openmoat policy diff OLD NEW --widen` decides both policies over the bundled calls, cases generated from both policies' rules (each pattern's matches and near misses, host lookalikes, shell argument lists, each request rule's methods and paths, the defaults) and `--fixtures` files, lists every call that moves toward allow (deny > review > defer > allow) with the rules before and after, and exits 2 when something widens. For file, host, fetch, environment and MCP rules it also searches every subject and, when the search finishes, proves no subject widens; shell commands, request rules and whole calls are checked over cases only, and the output says which. `openmoat policy upgrade` lists what an upgrade widens and applies it only with `--accept-widening`; `openmoat trust` and `openmoat policy install` show what trusting a repository policy or installing a pack widens; `openmoat policy check-diff --base`, and so the merge check, fails a change whose policy file widens with `diff-widens` (docs/POLICY.md §8.3, ADR-111) ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
