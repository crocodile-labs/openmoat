### Security
- Reading or copying a folder that holds files a deny rule names now asks (`protected-contents`, ADR-038). Before, `cp -r ~/.codex /tmp/c`, `grep -r token ~/.gemini`, `tar czf a.tgz ~/.hermes`, `rsync -a ~/.local/share/opencode x`, `zip -r a.zip ~/.copilot` or `cp -r ~/.docker x` deferred: the classifier sees one read of the folder, and `agent-credentials` and `secrets-paths` name files inside it. Every deny rule's paths now protect the folders they lie in, in every spelling (moved agent directories, other case on macOS and Windows), for reads and for writes into the folder. `ls ~/.codex`, `ls ~/Library` and `ls /` ask too; folders inside a project are unchanged, so `grep -r TODO .` stays allowed. Hosts that cannot ask deny it with the `openmoat allow --last` hint ([#667](https://github.com/crocodile-labs/openmoat/pull/667)).
- An extraction is a write of the folder it extracts into: `tar -x … -C DIR` (`--directory`, also `gtar` and `bsdtar`) and `unzip … -d DIR`, or the working directory without one. `tar xf e.tar -C ~/.claude` and `unzip e.zip -d ~/.moat` were deferred and are now denied by `kernel-self`; `tar xf e.tar -C ~` is denied by `destructive` ([#667](https://github.com/crocodile-labs/openmoat/pull/667)).
- `git checkout [<tree-ish>] [--] <path>…` writes each path, as `git restore` does: `git checkout main -- .github/workflows/ci.yml` and `git checkout .claude/hooks/x.sh` ask (`runs-later`) instead of deferring or being allowed, and `git checkout -- ~/.claude/settings.json` is denied; `git checkout -- src/main.rs` and `git checkout main` are unchanged ([#667](https://github.com/crocodile-labs/openmoat/pull/667)).
