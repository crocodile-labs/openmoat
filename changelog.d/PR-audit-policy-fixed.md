### Fixed
- `card-egress` no longer denies ordinary ids: a contiguous 13 to 19 digit number counts as a card only in a card's context (the value of a field named like a card's, `card`, `cardNumber`, `cc`, `pan`, `card[number]`, …, or sent beside a security code or expiry such as `cvv` or `exp`), so a GitHub repository or job id in an API path, an order id or a number in a query or a search is no longer denied. Card numbers in printed groups (`4000 1234 5678 9017`) count wherever they are (ADR-052, amended) ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- `git config user.name`, `git config user.email` and other `git config <section>.<key>` reads with nothing after the name (also after one scope option such as `--global`) are allowed like `git config --get`; a value after the name, or a subcommand such as `edit`, still needs review ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- `for n in 1 2; do sed -n "$n"p f; done` and `sed -n $n'p'` are read as the shell reads them (`${n}p`) and allowed like `sed -n "${n}p"`, instead of needing review ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
