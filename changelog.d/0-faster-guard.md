### Changed
- Faster checks. `openmoat status`, `doctor`, `init`, `watch` and `hooks` read and compile your policy for the hook ledger only when one of the agents' other hooks is new or changed, not on every run. The never-widen check (`policy diff --widen`, `policy upgrade`, `trust`, `policy install` and the merge check) searches about twice as fast when a change widens: 127 s down to 54 s on the 0.24.0 default policy in a debug build. Debug builds, which the tests run, now optimise the YAML, glob, regex and SQLite libraries they use: each `openmoat guard` call takes about half the CPU time it did (0.65 s down to 0.31 s per call in a debug build), and `status`, `doctor` and `init` about 40% less. Release builds were already optimised, so their guard is unchanged. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))
