### Security
- `openmoat run` no longer starts an agent whose project turns its OpenMoat hook off as the session starts (Claude Code or GitHub Copilot CLI `disableAllHooks`, a trusted Codex project's `features.hooks`, Gemini CLI `hooksConfig.enabled`, a pi `extensions` exclusion, an OpenCode `-openmoat` entry, a goose `disabledPlugins` entry or project plugin named `openmoat`, an Antigravity CLI `.agents/hooks.json` entry): it reads every folder from the working directory to the project root, names the file and the way out, and records the refusal. Claude Code starts with `--settings '{"disableAllHooks":false}'` on every run, so settings it reloads mid-session cannot turn the hooks off either (not when you pass your own `--settings`, and not when your own settings turn hooks off, which it says). An OpenCode file using `{env:…}`/`{file:…}` substitution and a Codex profile's `features.hooks = false` count too. The person's own policy can say `sandbox.project_hook_off: start`, honoured only while the policy lock holds, which a repository policy cannot, and each such run is recorded (ADR-098) ([#9603](https://github.com/crocodile-labs/openmoat/pull/9603)).
- `openmoat init --managed` also writes OpenMoat's hook where an administrator's hooks live, which a repository's settings cannot turn off: Claude Code's `managed-settings.d/50-openmoat.json`, GitHub Copilot CLI's `policy.d/openmoat.json`, Cursor's enterprise `hooks.json` (only while it is missing or OpenMoat's alone). It needs a person at a terminal, prints the `sudo install` command where the file needs root instead of escalating, never edits an administrator's own file, and `openmoat uninstall` removes it; `openmoat doctor` reports it. The default policy's `managed-settings` rule now also covers Copilot CLI's `policy.d` and Cursor's and OpenCode's system folders (ADR-098) ([#9603](https://github.com/crocodile-labs/openmoat/pull/9603)).
