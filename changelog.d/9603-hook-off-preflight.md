### Security
- `openmoat run` no longer starts an agent whose project turns its OpenMoat hook off as the session starts (Claude Code or GitHub Copilot CLI `disableAllHooks`, a trusted Codex project's `features.hooks`, Gemini CLI `hooksConfig.enabled`, a pi `extensions` exclusion, an OpenCode `-openmoat` entry, a goose `disabledPlugins` entry or project plugin named `openmoat`, an Antigravity CLI `.agents/hooks.json` entry): it names the file and the way out. Claude Code starts with `--settings '{"disableAllHooks":false}'` where that covers it; the person's own policy can say `sandbox.project_hook_off: start`, which a repository policy cannot, and each such run is recorded (ADR-095) ([#9603](https://github.com/crocodile-labs/openmoat/pull/9603)).
- `openmoat init --managed` also writes OpenMoat's hook where an administrator's hooks live, which a repository's settings cannot turn off: Claude Code's `managed-settings.d/50-openmoat.json`, GitHub Copilot CLI's `policy.d/openmoat.json`, Cursor's enterprise `hooks.json` (only while it is missing or OpenMoat's alone). It needs a person at a terminal, prints the `sudo install` command where the file needs root instead of escalating, never edits an administrator's own file, and `openmoat uninstall` removes it; `openmoat doctor` reports it. The default policy's `managed-settings` rule now also covers Copilot CLI's `policy.d` and Cursor's and OpenCode's system folders (ADR-095) ([#9603](https://github.com/crocodile-labs/openmoat/pull/9603)).
