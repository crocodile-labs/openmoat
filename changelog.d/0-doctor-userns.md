### Added
- On Linux, `openmoat doctor` warns when an agent's own sandbox that `openmoat init` turned on cannot start commands on the machine: Claude Code's needs `bwrap` and `socat` on `PATH`, and Claude Code's, Codex's and Cursor's need to create user namespaces as the user, which Ubuntu's AppArmor restriction, `user.max_user_namespaces=0`, Debian's `kernel.unprivileged_userns_clone=0` or a container can refuse. The line says what the agent then does and the fixes (an AppArmor profile for `bwrap`, or the `sysctl` setting and its `/etc/sysctl.d/` file); `openmoat status` shows one line under "Needs your attention" and lists the same as `own_sandbox_linux` in `--format json`. What each agent needs comes from its spec and documentation; nothing runs as root and no decision changes. The weekly latest-agent check reports Claude Code's sandbox failing on the CI runner's nested user namespace as a `skip  env-limit` line instead of a failure, and still requires the `SessionStart` row, the denied read and no other tool failure ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
