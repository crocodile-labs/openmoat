### Added
- Short-lived brokered secrets (preview): a secret's `source: { command: { run: [...], lifetime: 15m } }` names a program, such as a cloud CLI's token command, that `openmoat proxy` runs for the value, uses it for at most `lifetime` (1 minute to 12 hours, or less when the program prints an expiry) and runs again before it ends, on a thread of its own. Past its deadline a request that needs the value is refused before anything is sent and recorded as `proxy-secret-expired`; a stale value is never sent. The program runs only when a deny `fs.write` rule covers it or only an administrator can change it, never from `/tmp`, pinned by its SHA-256 for the life of the proxy, with no input, a bare environment, a 30-second limit and 64 KiB of output; its output is never quoted and every value it gave is masked in the audit log. `openmoat guard`, audit delivery and Claude Code's broker never run it, and a repository policy or pack cannot add one (`docs/POLICY.md` §2.2, ADR-087) ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source's program starts in `/`, never in the agent's project, with an empty home of its own under OpenMoat's state folder; `home: user` gives it your home for a tool that keeps its login there ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source's program finds tools in the system's folders only, never its own; every folder above it, up to your home, must be kept from the agent as the file is, and a script's interpreter must pass the same check and is pinned too (`#!/usr/bin/env` is refused). The example is now Vault's CLI, not `gcloud`, whose Python loads from folders you can write ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- The proxy runs a private copy of the bytes it hashed, checked again before each run, never the file at the program's path; a deny rule counts as proof only outside the project and `openmoat run`'s write roots, where only root ownership does ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- On macOS and Linux the time limit ends a `command` source's whole process group, and its output is read with a deadline, so a child it left holding its output neither outlives the run nor keeps a thread of the proxy waiting ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- A `command` source is renewed from the lifetime its value actually got (the shorter of `lifetime` and the expiry it printed), a fifth of it before the end, at least a minute ahead and at most once a minute after an answer, each secret on its own thread; a program that printed an expiry shorter than `refresh_before` was run on every look ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- Under `openmoat run`, a repository policy's deny rules no longer count as proof that the agent cannot change a `command` source's program; only your own policy's do ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
- `openmoat guard`'s audit rows do not mask a `command` source's value: OpenMoat does not write the values to a file for it, which would be a copy on disk of the tokens the source keeps short-lived; LIMITS.md says so ([#793](https://github.com/crocodile-labs/openmoat/pull/793)).
