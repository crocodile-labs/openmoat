### Security
- The audit log is keyed: each event now carries a MAC of its chain hash under a per-install key, `~/.moat/audit.key`, which `openmoat init` (or the first call after the upgrade) makes owner-only and the default policy keeps from agents. Someone who can change `audit.db` but cannot read the key can no longer rewrite events so that the log still verifies; `openmoat doctor`, `openmoat audit verify --against` and `openmoat audit anchor` report the first event whose MAC is missing or wrong. Events written before the upgrade keep verifying by their hashes only. If the key is deleted while the log holds keyed events, OpenMoat records nothing more and every call is denied until it is put back, or the log is moved aside and `openmoat init` starts a new one. Exports of keyed events are `moat-audit-export-v2` lines with the MAC and the key's id; `openmoat audit verify` checks the MACs on the machine that holds the key. Code running as you outside any sandbox can read the key too, so anchors kept off the machine stay the defence there (ADR-100). After upgrading, restart a running `openmoat proxy`, `openmoat approvals listen` and any agent with a wrapped MCP server: a process of the older build refuses to record until it is restarted.
