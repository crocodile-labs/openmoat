### Security
- The lethal trifecta: once a session has read private data (a secret, an agent's or a build tool's credentials, a decoy key, the whole environment, or a file `taint.private_paths` names) and content someone else may have written (a page, a search, an MCP result, an issue read with `gh`), every call that can send data out, to an allowed host too, needs review with rule `lethal-trifecta` and a reason naming both reads; `taint: { trifecta: deny }` denies instead. Sessions that never read private data are unchanged ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- Staging is decided, not only recorded: the default policy's new `staging-egress` rule reviews a send of a file the session packed from files outside the project, and any send after the session wrote private data into a file (`cp ~/.aws/credentials notes/`, then `git push`). A send after many outside reads with nothing packed stays recorded until its thresholds are measured. Run `openmoat policy upgrade` to add the rule to an existing policy ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- Injected input is linked across more spellings: a percent-encoded host, a relative path placed against the directory it was read in (`../x` was read as `/x`), and a command written with its program's directory, `./` or `~` ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
