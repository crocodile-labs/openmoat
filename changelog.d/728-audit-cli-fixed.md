### Fixed
- The first hook call after upgrading from 0.13 no longer copies the whole audit log to accept the `review` verdict: the schema step now widens its check in place, in milliseconds at any size. On a large log the copy ran past the guard's 30 s budget, was rolled back and started again on the next call, so every call was denied ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- Loading the policy on each hook call is faster: the check for the old `ask` name no longer parses the default policy a second time, and merging a repository policy, a pack or `openmoat allow` rules no longer parses every pattern of the policy again (about 14 ms less per call with a repository policy) ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- When a call's provenance, MCP ticket or `openmoat run` link cannot be written after its row, the audit log now also records the deny the host was given, so the log's last word on the call matches the answer ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- A panic while the guard decides is denied in the format of the payload's event (a `ConfigChange` is blocked as one), not always as a tool call ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
