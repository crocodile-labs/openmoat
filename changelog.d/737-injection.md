### Security
- Prompt-injection data flow (ADR-057). When Claude Code reports what a call returned (a new `PostToolUse` hook entry), and the output is untrusted (a fetched page, web search results, an MCP result, `gh issue view`, a `curl` of an unlisted host), OpenMoat keeps keyed fingerprints of its URL hosts, host-like words, outside paths and code-span commands, never the text. A later shell command or write that uses one of them, such as `curl` to the host an issue body named, needs review (`injected-input`), and the reason names the source. Anything the policy allows on its own stays allowed (builds, project files, the registries, `git push`), and fetches and searches stay the agent's own prompt. Run `openmoat init` once to add the hook entry; `openmoat doctor` reports it as needed until then. Other agents do not report output yet, as each HOST.md says ([#737](https://github.com/crocodile-labs/openmoat/pull/737)).
- After the session reads untrusted content, writes to `.agents/skills/**`, `.windsurfrules`, `.windsurf/rules/**` and `.github/instructions/**` (instruction and skills files the next agent session obeys) need review, as `CLAUDE.md` and `AGENTS.md` already did. In a clean session they stay ordinary edits ([#737](https://github.com/crocodile-labs/openmoat/pull/737)).
