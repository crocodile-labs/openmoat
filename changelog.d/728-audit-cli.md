### Security
- The audit log now masks more passwords and keys before it stores a command: `mysql -p<password>`, `PGPASSWORD=`, `MYSQL_PWD=` and other environment names ending in `PASSWORD`, `_KEY`, `_SECRET`, `_TOKEN` or `_AUTH`, `sshpass -p`, `docker login -p`, `redis-cli -a`, `openssl -k` and `-pass pass:`, `zip -P`, `htpasswd -b`, `Cookie:` and `Set-Cookie:` values, `aws configure set aws_secret_access_key`, Slack and Discord webhook URLs, and a key given as the user part of a URL (a Sentry DSN). The same flags of other programs (`cargo test -p`, `ssh -p`, `mkdir -p`) keep their values ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- An agent can no longer run `openmoat guard` or `openmoat mcp proxy` from its own shell tool (`kernel-self`): only a host runs them, so an agent cannot write audit rows, MCP tickets or a session's proxy credential for payloads it made up. `--help` still works ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- `openmoat allow --last` and `openmoat policy upgrade` (and `--undo`) refuse to re-pin when a pinned file or the lock changed while they waited for the answer, instead of pinning the change unseen ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- The guard works out again whether an agent's OS sandbox is in place when Claude Code's `blockReadsOutsideWorkingDirectories` is turned off, so code a session wrote is held for review at once rather than after the next re-pin ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
- The `openmoat run` Seatbelt profile also denies hard links (`file-link`) to every path it denies reading or writing, so a sandboxed command cannot link `~/.moat/proxy.key` or `audit.db` into the project ([#728](https://github.com/crocodile-labs/openmoat/pull/728)).
