### Added
- Windows, preview: `openmoat agent-account setup` now also installs Windows Filtering Platform filters for the agent account (a persistent OpenMoat provider and sublayer, a block at the connect, listen and receive-accept layers for IPv4 and IPv6, and one permit to `127.0.0.1` and `::1` on a range of eight ports it records), so Windows refuses every connection and listen the agent makes but one to the run's proxy, whether or not a program honours `HTTP_PROXY`. `openmoat run` as the account puts its proxy on the first free port of that range, records the network as `wfp_account` and names the name lookups that still leave through Windows' DNS Client service as a `dns` downgrade; once the filters are read back as recorded the run scores 100/100, so `sandbox.strict: true` and `require.run: full-boundary` accept it. `status` compares the filters with the record and exits 1 on drift, and `remove` deletes them. An account set up before keeps its 70/100 run, `status` says it has no filters, and `setup` again, from an administrator terminal, adds them (ADR-129) ([#865](https://github.com/crocodile-labs/openmoat/pull/865)).
