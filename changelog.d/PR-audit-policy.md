### Security
- Writes to the git hook folders a repository's `core.hooksPath` usually names (`.githooks/`, `.git-hooks/`, `githooks/`, `git-hooks/`, `scripts/git-hooks/` included, and the folders themselves) need review (`runs-later`) and are in the session taint list; before, a write there was allowed by `project-fs`, though git runs those files on the next commit or push. Folders merely named `hooks` (React hooks, docs) stay ordinary writes ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- Writes to Cline's workspace hooks (`.clinerules/hooks/`, `.cline/hooks/`, every file of which Cline runs on each tool call) and renames onto `.clinerules`, `.cline` or their `hooks` folders need review (`runs-later`), as other agents' project hook folders do; before, `project-fs` allowed them. Rules files in `.clinerules/` stay ordinary writes ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- A quote or a backslash now ends a variable's name, as in the shell: `d=~/.ssh/id; cat "$d"_rsa` (also `$d'_rsa'`, `$d"_rsa"`, `$d\_rsa`) is a read of `~/.ssh/id_rsa` and denied by `secrets-paths`, and `echo "$GITHUB_TOKEN"x` reads `GITHUB_TOKEN` (`env-secrets`); before, they were read as the unknown variables `d_rsa` and `GITHUB_TOKENx` and deferred ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- An editor (`vi`, `vim`, `nvim`, `nano`, `emacs`, `code`) saves the file it opens, so its file operands are decided as writes too: `vim /usr/local/bin/openmoat` and `nano ~/.moat/policy.yaml` are denied by `kernel-self` and `nvim ~/.zshrc` by `shell-rc`, as writing them is; an editor on a project file keeps its verdict ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
