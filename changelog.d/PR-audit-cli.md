### Security
- The audit log now masks more passwords and keys before it stores a command: `mysql -p<password>`, `PGPASSWORD=`, `MYSQL_PWD=` and other environment names ending in `PASSWORD`, `_KEY`, `_SECRET`, `_TOKEN` or `_AUTH`, `sshpass -p`, `docker login -p`, `redis-cli -a`, `openssl -k` and `-pass pass:`, `zip -P`, `htpasswd -b`, `Cookie:` and `Set-Cookie:` values, `aws configure set aws_secret_access_key`, Slack and Discord webhook URLs, and a key given as the user part of a URL (a Sentry DSN). The same flags of other programs (`cargo test -p`, `ssh -p`, `mkdir -p`) keep their values ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- An agent can no longer run `openmoat guard` or `openmoat mcp proxy` from its own shell tool (`kernel-self`): only a host runs them, so an agent cannot write audit rows, MCP tickets or a session's proxy credential for payloads it made up. `--help` still works ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- `openmoat allow --last` and `openmoat policy upgrade` (and `--undo`) refuse to re-pin when a pinned file or the lock changed while they waited for the answer, instead of pinning the change unseen ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
