### Security
- `openmoat mcp proxy` speaks MCP 2026-07-28 beside the 2025 revisions, read from each message: it pins a server's `server/discover` answer (without the `ttlMs` and `cacheScope` cache hints) as it pins the `initialize` answer, and holds the whole server, all its calls refused, when a result's `_meta` server information is not the accepted one or changes mid-run; a server accepted under the older revision keeps its acceptance while its text is the same ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- The MCP gateway refuses a server's sampling requests unless the policy sets `mcp: { allow_sampling: true }`, and a URL-mode elicitation that is not `https`, carries credentials, or points at this machine, a private or link-local address (the cloud metadata service) or a host the policy denies; the same check covers a 2026-07-28 result's `inputRequests` ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- A tool's `x-mcp-header` mappings are named in `openmoat mcp accept` and a changed one holds the tool; a tool whose mappings break the specification's rules, or whose schema's `$ref`s leave it, loop or chain deeper than 16, is left out and its calls refused ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- Accepting a stdio MCP server records the package release its command runs (npm version and integrity from npx's install, a `uv tool` install's version, an image digest), read offline; a new release holds the server as a changed definition does, so `npx -y postmark-mcp` moving to a new release needs a person again ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
