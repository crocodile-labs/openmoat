### Added
- `openmoat bench --report` answers six security questions ("can an agent read ~/.ssh/id_rsa?", "can a build script read an agent's credentials?", "can MCP output steer a write?", "can data go out through an allowed host?", "can the agent turn OpenMoat off or edit its policy?", "does a hook crash or timeout fail closed?") one row per layer that holds each: the policy decision, the host hook, the OS sandbox (the attack run for real under `openmoat run` in a throwaway home) and the network boundary (the proxy's decision). Each row is PASS, FAIL or NOT TESTED HERE with the reason, never a pass for a layer that did not run here, with the OpenMoat version, the system and its version, each agent's version when found, and the scenario or probe id that reproduces it. Text, `--format json` and `--format markdown`; the command exits 1 when an exercised layer fails, for CI. `--scratch-dir` puts the throwaway home elsewhere (on Linux the OS rows need one outside `/tmp`) (ADR-065).
- MoatBench scenario `file-tool-reads-agent-login`: reading another agent's login file with a file tool is denied (`agent-credentials`).
