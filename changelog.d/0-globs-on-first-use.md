### Changed
- Compiling a policy builds a glob whose text cannot fail to parse (no `[`, `{`, `}` or `\`) only when a call first needs it, instead of all of them up front: a call uses at most a few of the 1,300 or more globs the default policy spells. Every other glob is still built when the policy is compiled, so a bad pattern fails as before. Should a glob built later fail anyway, every decision of that compile is the same `kernel-error` deny a compile error gives. No decision or error changes ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- A policy pattern is spelled once per home directory spelling only when it names `~`, and once per project spelling only when it names `${project}`; the folder check reuses the deny rules' spellings. The spellings are the same ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
- `openmoat bench` creates its throwaway home under the resolved temporary directory (`/private/var/…` on macOS), so the home has one spelling and the `compile` phase it reports is what a guard in an ordinary home pays ([#0](https://github.com/crocodile-labs/openmoat/pull/0)).
