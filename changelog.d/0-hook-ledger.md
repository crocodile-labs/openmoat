### Security
- A ledger of the hook commands, plugin hooks, program-running settings and git programs the agents load besides OpenMoat's hook, pinned in the policy lock (ADR-109): the hook file's other entries, helper commands such as `apiKeyHelper` and `statusLine`, a project's hook files and hook and plugin folders, Claude Code's installed plugins (`hooks/hooks.json` and the manifest's `hooks`), Cline's other hook files and `.git/config` programs (`core.fsmonitor`, `core.pager`, `core.sshCommand`, `!` aliases, …). While one is new or changed, `openmoat status`, `openmoat doctor` and `openmoat watch` name it with the shell classifier's verdict on its command until a person runs `openmoat hooks accept` in a terminal, and `openmoat hooks list` lists them. Only one whose command the classifier denies (a plugin update adding `curl … | sh`) changes the agent's calls: they are denied (rule `foreign-hook`) and `status` exits 64; any other is a warning. `hooks: { foreign: hold }` in your own policy holds the calls for review for every new or changed one instead. The first `openmoat init` after the upgrade records what is there, so nothing that was there before is blocked. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))
- Codex, Gemini CLI, Qwen Code and Crush now block a call when `openmoat` is missing or killed: the hook command turns any exit but the guard's own 0 or 2 into exit 2 with a reason, which each of them reads as a block. Run `openmoat init` again to rewrite the entries (Codex then asks you to trust the changed hook in `/hooks`). A hook that times out still runs the call there; the guard denies on its own after 30 s. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))
