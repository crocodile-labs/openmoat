### Security
- A ledger of the hook commands, plugin hooks, program-running settings and git programs the agents load besides OpenMoat's hook, pinned in the policy lock (ADR-109): the hook file's other entries, helper commands such as `apiKeyHelper` and `statusLine`, a project's hook files and hook and plugin folders, Claude Code's installed plugins (`hooks/hooks.json` and the manifest's `hooks`), Cline's other hook files and `.git/config` programs (`core.fsmonitor`, `core.pager`, `core.sshCommand`, `!` aliases, …). While one is new or changed, the calls of the agent that loads it are held for review (rule `foreign-hook`), or denied when the shell classifier denies its command (a plugin update adding `curl … | sh`), until a person runs `openmoat hooks accept` in a terminal; `openmoat status` and `openmoat doctor` name each with its verdict, and `openmoat hooks list` lists them. The first `openmoat init` after the upgrade records what is there, so nothing that was there before is blocked. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))
- Codex, Gemini CLI, Qwen Code and Crush now block a call when `openmoat` is missing or killed: the hook command turns any exit but the guard's own 0 or 2 into exit 2 with a reason, which each of them reads as a block. Run `openmoat init` again to rewrite the entries (Codex then asks you to trust the changed hook in `/hooks`). A hook that times out still runs the call there; the guard denies on its own after 30 s. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))

### Changed
- `openmoat status`, `openmoat doctor` and `openmoat watch` warn at once when a Claude Code session whose start reached OpenMoat called a tool OpenMoat's hook covers and no call of it reached OpenMoat, instead of after the session is ten minutes old. ([#0](https://github.com/crocodile-labs/openmoat/pull/0))
