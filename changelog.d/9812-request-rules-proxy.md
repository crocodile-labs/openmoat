### Added
- `requests:` in the policy: method and path rules (`allow`, `deny`, `METHOD /path`) for one allowed host each, held by the hook in commands and fetch tools and, without `hook_only: true`, by the proxy inside HTTPS with a proxy CA (`openmoat proxy ca init` now covers their hosts). The standalone `openmoat proxy` terminates those hosts for Claude Code sessions whose `SessionStart` hook gave them the CA's certificate (`$TMPDIR/moat-session-<id>-ca/`, the variables `openmoat run` sets) and a `v2` credential with the trust mark; `v1` credentials are still accepted for one release, never trusted. Another session's connection to such a host is refused (`requests_untrusted: refuse`, the default) or relayed unread (`relay`). A repository policy or a pack may add `deny` lists only. The `exfil-endpoints` pack source (`crates/openmoat-core/policies/packs/`) has the proxy hold the default policy's gist rules. The `OPENMOAT_ADR062_POC` proof-of-concept setting is removed, and its rule id `proxy-request-rule` becomes `request-rule` ([#9812](https://github.com/crocodile-labs/openmoat/pull/9812)).
- `openmoat doctor` and `openmoat status` say, where the host sandboxes use `openmoat proxy`, when a proxy CA exists but the `exfil-endpoints` pack is not installed (with the command that installs it), and when a `requests:` host the proxy holds is not covered by the CA (with `openmoat proxy ca init`); the proxy refuses such a host's connections through `requests_untrusted` instead of failing the handshake. MoatBench has an exfiltration scenario for an allowed host's gist endpoint ([#9812](https://github.com/crocodile-labs/openmoat/pull/9812)).
- **Breaking** `openmoat-proxy`: `Requests` is built with `Requests::new(entries, untrusted)` from the policy's `requests:` (`Requests::deny` still adds one host's deny rules) and `Requests::hosts` returns a `Vec`; `RequestRuleError` holds its message only; `Sessions::admit`, `Admitted`, `Trust` and `Tls::covers` are new, and `Verify` gains `trusted` (default `false`). `openmoat-core`: `Policy` has the new fields `requests` and `requests_untrusted`, and `RepoPolicy` the field `requests`; `RequestEntry`, `RequestRules`, `RequestCheck`, `RequestsUntrusted`, `REQUESTS_RULE_PREFIX` and `rule_id::REQUEST_RULE` are new, and `rule_id::PROXY_REQUEST_RULE` is gone ([#9812](https://github.com/crocodile-labs/openmoat/pull/9812)).
