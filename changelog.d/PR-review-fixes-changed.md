### Changed
- Cline CLI: `openmoat status` and `doctor` print Cline's limits on a line of their own (`cline --yolo` runs no hooks; another hook or plugin can rewrite a call after OpenMoat checked it; Cline runs the call when OpenMoat's script cannot start or is killed after 120 s), and name every other `PreToolUse` file in Cline's hook folders and every Cline plugin they find; `status --format json` lists them under `other_hooks` and gives each agent's `limit` ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- Linux: plain `openmoat run` says on standard error when it starts that commands the agent starts can still read and write the project's `.env`, create `.envrc` and write `.moat` and `.git/hooks`, and that `openmoat run --isolate` closes this (naming bubblewrap when it is missing); `openmoat doctor` warns about the same, and `status`, `doctor` and `init` name `openmoat run --isolate` for an agent without a sandbox of its own ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
- Docs: README "Limits" and THREAT_MODEL say plainly that agent login files are denied to the agent's own tool calls but stay readable to programs an allowed command runs, inside every OS sandbox too; ADR-054 (proposed) weighs the options and plans denying them in the host sandboxes that confine only the agent's commands ([#PR](https://github.com/crocodile-labs/openmoat/pull/PR)).
