### Security
- On Linux, what the policy denies inside the project now holds in every `openmoat run` tier (ADR-089). Without bubblewrap the project is granted entry by entry, so commands can no longer read `.env`, write `.git` or `.moat`, or create `.envrc` or a git hook there; the cost is that nothing new can be created directly at the project's top in that case. With bubblewrap, `--no-isolate` covers the project as `--isolate` does, so `.git` is read-only there too: commit outside the run. In both bubblewrap tiers a missing `.claude/hooks/`, `.github/hooks/` or other agent configuration folder in an existing holder is a read-only folder for the session, so a hook written there after the start is refused. `openmoat run` and `openmoat doctor` name each denied path that stays open ([#9203](https://github.com/crocodile-labs/openmoat/pull/9203)).
